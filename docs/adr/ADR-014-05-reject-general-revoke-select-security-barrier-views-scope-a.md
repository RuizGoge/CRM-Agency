# ADR-014 — ADR-API-05 — Reject general REVOKE SELECT + security_barrier views / scope-argument functions; adopt the targeted, generated form

**Status:** accepted (Phase 5, pending GATE 5)

## Context

The brief asks explicitly whether the app role should lose SELECT on base tables, with access granted only through security_barrier views or through functions that receive the scope as an argument, and whether Drizzle tolerates it and at what cost.

## Options considered

(a) Full adoption: revoke SELECT everywhere, one barrier view or accessor function per table. (b) Reject entirely and rely on FORCE RLS alone. (c) Targeted adoption, generated from security.table_registry: revoke base SELECT only where it buys something RLS cannot give.

## Decision

(c). Adopted for: every table carrying deleted_at (base SELECT revoked, security_invoker *_live view granted, so a query that 'forgets the filter' has nothing to query); column hiding (intake_source.token_hash is not in the readable view); definer-only tables (consent_ledger, suppression_list, tenant_lookup_meter — no SELECT at all, reachable only through app.compliance_check()/app.consent_state() which return a verdict and a reason code, never a row). Rejected for everything else. The views and GRANTs are generated by security.harden() from two new registry columns, never hand-maintained.

## Consequences

Four reasons the general form is rejected, recorded so it is not relitigated: (1) security_barrier defeats predicate pushdown for non-LEAKPROOF quals, and the hottest read is a keyset LIMIT 20 per column on a covering index — the exact plan a barrier view can force to materialize; this attacks a build-breaking p95. security_invoker views do not have this problem, which is why they are what the design uses. (2) A function taking scope as an argument is strictly weaker than RLS: an argument can be passed wrong, and it moves scope from a session fact the policy reads itself to a call-site parameter — reintroducing the 'someone forgets' surface FORCE removes. (3) Drizzle tolerance: pointing at a view is mechanical, but INSERT ... RETURNING requires SELECT privilege on the returned columns, so revoking base SELECT breaks .returning(); the workaround is minting uuidv7 in the application and banning .returning() in those repositories — a real, enumerable cost. (4) Full adoption doubles the relation surface as a hand-maintained artifact, which is the anti-pattern thesis non-negotiable 2 exists to prevent; generating it from the registry is the only acceptable form.
